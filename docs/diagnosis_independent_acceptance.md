# 多轮故障诊断独立验收

## 验收边界

本次验收用于检查结构化诊断状态对多轮客服任务的实际增益。验收集在执行引擎前完成结构校验并计算 SHA-256，之后未修改诊断引擎、规则配置或数据内容。

- 数据集：`data/diagnosis_independent_acceptance.csv`
- SHA-256：`75c2d74d54d578179ecf37fc389d89ee018cc0d66b25b8c4a26b802d4a3fd215`
- 会话数：36
- 对话轮次：87
- 终态分布：16 个解决、15 个人工升级、5 个取消
- 与既有基础集和困难集完全重复的 query：0

该数据由项目内人工构造的新表达组成，未参与此前规则优化。它属于冻结的独立验收集，不是真实生产流量、第三方盲测或线上 A/B 实验。

## 对照方法

相同会话按两种方式重放：

- Stateful：同一会话复用稳定 `session_id`，读取 SQLite 中的结构化诊断状态；
- Stateless ablation：每个轮次使用独立 `session_id`，不保留前序诊断状态。

`task_completion_rate` 只统计最终应进入 `resolved`、`escalated` 或 `cancelled` 的会话。`unnecessary_repeat_question_rate` 统计后续轮次中不符合标准动作的症状或结果重复追问。

## 失败审计

Stateful 仍有 13 个会话未达到预期终态，主要原因如下：

- 故障或反馈表达未被词表归一，例如“声音完全消失”“能用了”；
- 安全与人工意图漏识别，例如“电池外壳鼓起来”“安排售后人员处理”；
- 取消表达漏识别，例如“先暂停后面再查”“不用再检查了”；
- 个别自然反馈被当作信息不足，或者提前触发升级。

结果说明 SQLite 状态保持和状态机显著改善了多轮连续性，但确定性词表仍是整体完成率的主要瓶颈。后续若优化语义识别层，本验收集只能作为历史基准，不能再作为新的独立测试集。

## 简历使用边界

当前可以准确表述为：

> 在 36 个冻结多轮验收会话上，相较无状态消融基线，使诊断任务完成率由 25.0% 提升至 63.9%，无效重复追问率由 92.2% 降至 19.6%。

该表述可复现且没有夸大，但 63.9% 的绝对完成率仍偏低，不建议现在就作为最终简历版本。后续已转向“诊断契约 + 结构化观察 + 约束状态迁移”：步骤级契约负责定义可验证的成功/失败观察，观察提取器不直接修改状态。契约改造后的结果只能使用另一套全新冻结数据验收，不能回写本报告中的数据。
