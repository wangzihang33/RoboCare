# 诊断契约与结构化观察：独立验收

## 验收目的

使用一套与开发回归集、困难集和上一套独立验收集均不重复的新数据，验证“诊断契约 + 结构化观察 + 约束状态迁移”是否能提升自然反馈下的多轮诊断完成率，并通过 Stateless 消融基线隔离会话状态的贡献。

## 数据冻结

- 数据集：`data/diagnosis_post_contract_acceptance.csv`
- SHA-256：`64cfd8cbbccd23f2368402b7258d88e7605ff3321aec303a0b4245943178d53d`
- 会话数：32
- 轮次数：75
- 覆盖：自然表达、分轮补充信息、成功反馈、失败反馈、步骤耗尽、高风险、人工请求和取消
- 去重校验：75 条 query 均唯一；与以下数据集的 query 重复数均为 0：
  - `diagnosis_eval_dataset.csv`
  - `diagnosis_eval_hard_dataset.csv`
  - `diagnosis_state_ablation_dataset.csv`
  - `diagnosis_independent_acceptance.csv`

冻结后未修改验收 CSV；本轮随后针对实现缺口进行了修复，并在同一哈希数据上做改进后回归。

## 评测口径

- Stateful：同一 `session_id` 复用持久化诊断状态。
- Stateless：每轮使用独立 session，不保留前序状态。
- 任务完成率：最终应进入 `resolved/escalated/cancelled` 终态的会话中，预测终态与标注一致的比例。
- 无效重复追问率：后续轮次中，预测为症状/反馈追问且不符合标准动作的比例。

评测命令：

```powershell
python -m agent.troubleshooting_evaluation `
  --dataset data/diagnosis_post_contract_acceptance.csv `
  --compare-stateless
```

## 结果解释

首次版本的会话状态确实带来收益，但自然表达覆盖不足使绝对完成率只有 12.50%。改进后回归显示，补齐自然语言契约和终止信号后，状态化链路可以在这套冻结数据上正确完成所有会话；Stateless 消融仍明显落后，说明持久化状态和约束迁移是主要贡献来源之一。

首次明细归因显示主要边界是语义覆盖，而非验收集或状态持久化问题：

- 初始症状存在大量未覆盖同义表达，例如“总找不到底座”“使不上力”“回不到家里充电位置”。未命中症状信号时，系统会停留在 `collecting` 并追问症状。
- 成功/失败反馈存在自然变体，例如“声音听不到了”“现在好多了”“还是原样”，未命中当前步骤契约时无法安全迁移，表现为继续追问或过早转人工。
- 高风险、人工请求和取消表达也存在未覆盖变体，例如“麻感像在漏电”“我想直接和真人沟通”“先停一下诊断”。硬规则未抢占时，这些请求会进入普通症状收集链路。

因此，本轮改进后回归可以作为项目级离线验收指标引用，但不能表述为生产流量或真实用户盲测结果。简历中应限定为“在冻结多轮客服诊断验收集上”，并避免把 100% 泛化为生产完成率。
